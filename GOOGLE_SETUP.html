營養茲返回 App ↗
私人版 · 一次性設定

讓飲食日記，住進自己的雲端。

資料庫已建立。完成下列 Google 設定後，就能在 App 登入並同步私人試算表。整個流程不需要提供 Google 密碼、Client Secret 或 API 金鑰給 App。

目前狀態：私人試算表與連線程式已備妥；Google OAuth Client ID 尚待設定。此頁面不會代替你授權，也不會公開試算表。

01　確認私人資料庫

請使用你選定的工作帳號開啟營養茲個人飲食資料庫 ↗。保持「限制存取」，不用改成知道連結的人可檢視或編輯。

你會看到：使用說明、飲食紀錄、自訂食物、設定、食物資料庫五個分頁。

02　建立 Google Cloud 專案

開啟 Google Cloud 建立專案 ↗，專案名稱填「營養茲個人 App」。建立完成後選取這個專案。

接著在 Google Sheets API ↗ 按「啟用」。此版使用 Sheets API 的登入授權，不需配置 AI API 或付費模型。

03　設定 OAuth 同意畫面

開啟 Google Auth Platform → Branding ↗，應用程式名稱填「營養茲」，支援信箱與聯絡信箱選你自己的工作信箱。

  • 若工作帳號可選 Internal／內部，且只供自己或同組織使用，可選內部。
  • 若只能選 External／外部，先保持 Testing／測試中，在 Audience → Test users 加入你會使用的 Google 帳號。
  • 確認 Google 顯示的條款與資料使用規範後，由你決定是否接受。

04　新增 Google Sheets 存取範圍

在 Google Auth Platform → Data Access 新增：

https://www.googleapis.com/auth/spreadsheets

這個 scope 允許以你身分讀寫 Google 試算表。Google 的授權範圍不限於這一份表；營養茲程式只對設定的資料庫 ID 發出請求。請自行確認授權內容。

05　建立網頁版 Client ID

開啟 Google Auth Platform → Clients ↗，按 Create client，類型選 Web application／網頁應用程式。

名稱：營養茲 GitHub Pages

在 Authorized JavaScript origins／已授權的 JavaScript 來源 加入：

https://roroo0902.github.io

這裡不包含 /Dietitian/，也不需要 redirect URI。若 Google 規則或介面要求額外資料，依官方畫面提示填寫。

建立後，複製以 .apps.googleusercontent.com 結尾的 Client ID。不要複製 Client Secret。

06　回到 App 完成第一次同步

  1. 開啟營養茲 App →「設定與備份」。
  2. 展開「第一次設定 Google 登入」，貼上 Client ID，確認試算表 ID，按「儲存連線設定」。
  3. 按「登入 Google」，選有試算表編輯權限的帳號，查看並確認 Google 授權畫面。
  4. 若這個裝置已有紀錄，選「以本機覆蓋雲端」，把目前資料移入資料庫；若雲端已有你要的紀錄，選「採用雲端資料」。
  5. 看到「已儲存至 Google Sheet」或「已採用雲端，已啟用自動儲存」後，新增、編輯與刪除會自動保存。可開啟試算表核對。
請先匯出 JSON 備份。同步前會保存一份本機復原點。個人版請避免兩個裝置同時修改；自動同步會檢查已知雲端變動，但 Google Sheets 沒有提供此實作可用的完整資料庫交易鎖。

遇到問題時

  • origin_mismatch：確認 Client ID 的來源是上面的網址，並從正式 GitHub 網站開啟。
  • access_denied：確認帳號已列入測試使用者，或詢問工作帳號的 Google Workspace 管理員是否限制此 App。
  • 403：確認 Sheets API 已啟用，且登入帳號可以編輯指定的資料庫。
  • 在 App 內無法登入：用 Chrome 或 Edge 開啟正式網站再登入；Google 可能阻擋內嵌瀏覽器登入。
  • 授權到期：再次按「登入 Google」。短期 token 僅保存在記憶體，重新整理後需重新登入。
  • 顯示雲端有另一份資料：自動同步已停下，先確認要保留哪份，再採用雲端或以本機覆蓋。
